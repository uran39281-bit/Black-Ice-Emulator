# BC-1 v0.5 — Motion & Layers

Continues v0.4 on `bc-1-v0.5-motion`. Previous version branches and their APKs remain intact. V1 dark/icy-blue styling and automatic/manual phone/wide layout selection remain the design contract. 3D Page Curl is still excluded.

## Editing model

Schema 2 adds source-time keyframes and explicit layer placement. Schema 1 projects still open with defaults. The first save of a schema 1 project preserves its original JSON in a `.v1-backup` file. Project bundles restore with a new UUID and copy of the media, never overwriting another project.

V0 is the original sequential main video lane, including the seven bounded transitions. V1–V3 are independently positioned video/image lanes above V0; A1–A4 are independently positioned audio lanes. Same-lane overlaps are rejected; use a different lane to overlap clips. Timeline duration includes all clips. Text and image overlays retain independent start/end times and composite above video. The existing music bed remains available.

A selected clip's Layer / timeline start dialog sets its lane and absolute start. Trim, split, duplicate, reorder, undo/redo, snap, horizontal zoom and vertical timeline scrolling remain available. Splits retain source-time animation. Keyframe values before/after the keyed interval hold at the first/last value. Clip transformations and effect animation use source time; overlay animation uses time relative to the overlay's start. Position, uniform scale, rotation, opacity and clip effect intensity are animatable. Per-interval cubic Bézier curves have editable numeric controls, draggable handles, and Linear/Ease in/Ease out/Smooth presets. This is a normalized easing graph, not a full timeline dope sheet.

## Rendering and audio

The same composition is used by preview and export. GLES 3 shaders apply transforms, effect strength, opacity and optional chroma key. Chroma key exposes key color, tolerance, edge softness and spill removal. Independent video lanes are composited in descending lane order over the two alternating main-lane streams. Physical hardware decoding remains selected normally; the v0.4 Goldfish emulator decoder exclusion is retained.

Extract audio makes an independent audio clip referencing the retained source, with optional original muting. It does not re-encode or destructively alter the source. Audio clips have trim, offset, gain and fade-in/out controls. Waveforms are decoded PCM peaks generated on the worker executor on request; they are not synthetic graphics. Decoding is bounded to two minutes of processing time. Preview/export still require at least one visual clip. Export remains H.264/AAC 1080p with a 30 fps cap.

The portable model and Motion curve evaluator have no Android dependency. A future RTX backend can consume their timing, properties and effect IDs; this version does not implement desktop rendering.

## DeX and mouse controls

Space plays/pauses; S splits; Ctrl+S saves; Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y undo/redo; Ctrl+D duplicates; Delete removes; arrows step approximately one 30 fps frame, Shift+arrows one second. Text fields retain typing behavior. Ctrl+wheel zooms the timeline; wheel scrolls horizontally. Right-click offers clip actions. In wide mode, drag the divider to resize the tools, or long-press the inspector heading and drag to the left/right half to dock it. Dock side and width persist.

## Portable bundles

Setup → Export project + media bundle writes ZIP content with `project.json` and deduplicated `assets/NNNN.media` entries. Setup → Restore project bundle verifies entry names, rejects path traversal and duplicates, checks asset references, limits entries and expanded size, and keeps a storage reserve. Restoring creates a distinct project and local asset directory. Bundle export can be large because it includes original imported media. Keep the app open until the operation completes; bundle operations are not a foreground service.

## Limits and verification

100 clips, 20 overlays, 200 keys per property, four visual lanes and four independent audio lanes plus the music bed. Main-lane transitions may use two decoders, so an overlap with all upper video lanes can require five simultaneous video decoders. Available codec instances and sustained speed depend on the actual device. No Snapdragon/DeX performance or thermal measurements are claimed from emulator tests. There is no audio normalization, unlimited layering, GPU waveform decoding, or arbitrary panel layout persistence.

The final delivery QA record specifies the exact tested commit, APK checksum and emulator results. CI APKs use an ephemeral signing key; the delivered preview is signed with the retained BC-1 preview key so it can update v0.3/v0.4 Preview installations.
