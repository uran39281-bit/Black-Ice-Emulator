# BC-1 v0.4 — Video Timeline & Export

Built on `bc-1-v0.3-effects`; the original still-image workbench remains accessible from Setup.

## Project contract

`editor/EditProject` is an Android-independent edit decision list. Millisecond source ranges, ordered clips, transition IDs, overlay timing/position and music settings are serialized by `ProjectStore` to versioned JSON. Each project has a distinct UUID and an atomic save file. Import copies media into app-private storage. No media is modified by trims or splits. Removing clips retains their source files so undo and other projects remain safe.

`CompositionFactory` is the Android backend adapter. It builds the same Media3 composition for CompositionPlayer preview and Transformer export. A future desktop/RTX backend should consume EditProject and implement the effect IDs without depending on Activity, MediaCodec or content URIs. URI-to-asset resolution is an explicit backend boundary; this release does not implement an RTX renderer or desktop project interchange.

## Video, transitions and effects

Two alternating video sequences bound concurrent video decoding to two streams. Gaps extend both sequences over the project duration; compositor visibility hides inactive gaps. Overlaps are bounded to half each neighboring clip, preventing three simultaneous clips. The top stream's alpha mask exposes the other stream; the lower stream remains opaque. Timeline timestamps drive dissolve, wipe, checker, radial, slide, zoom and dip-to-black. 3D Page Curl is excluded.

The GLES 3 video shader ports all twelve existing effect choices, including None. Dynamic blur and bloom use a bounded 13-tap Gaussian approximation; the original still-image lab retains its separable cached blur. Tone mapping targets SDR. GPU decode surfaces remain on-device; there is no per-frame CPU video readback. Text/image overlay bitmaps update only when visibility changes. No Snapdragon performance numbers are claimed without device measurements. Export avoids the Goldfish host decoder on Android emulators after repeated-export buffer-pool failures in CI; physical devices retain default hardware decoder ordering with initialization fallback.

Preview can use 360, 540 or 1080 pixels on the short edge. Output is 1920×1080 or 1080×1920 independently of workspace layout. Frame dropping limits output to 30 fps; lower-frame-rate inputs retain their cadence (this is not optical interpolation or guaranteed constant-frame-rate conversion).

## Audio and export lifecycle

Clip audio and one independent, trimmed music track are mixed. Music supports timeline offset, gain, looping and removal. Clip and music volume are independent. Audio overlaps are mixed without automatic loudness normalization; lower clip gains when using overlapping loud sources.

Export uses H.264/AAC and an 8 Mbps video request. Encoder resolution fallback is disabled in the deliverable, so unsupported devices report an error instead of silently exporting a different resolution. Preview releases decoders while the foreground export service runs. The user chooses a destination with Android's document picker. Encoding first writes a private temporary file, then copies the completed MP4 to that destination. Cancel/error attempts to remove an incomplete destination; document providers may refuse deletion. The export service is not automatically resumed after process death.

## UI and storage

The V1 dark/cyan palette, phone monitor, timeline and tool tabs are retained. LayoutPolicy still chooses phone/tablet/DeX chrome independently of project aspect. Explicit mode choices persist. Wide mode needs a sufficiently wide window; compact phone windows scroll. The timeline supports selecting clips, scrubbing the ruler, edge snapping and zoom. Reordering uses Earlier/Later buttons. Undo/redo covers the current editing session; saved project files persist across launches.

This preview supports 100 clips and 20 text/image overlays. Import requires free internal storage and keeps private source copies. Projects are retained when the app updates with the same package/signature, but uninstalling removes app-private media and projects. v0.3's still-image session storage is untouched.

## Build and checks

JDK 17, Gradle 8.11.1, Android Gradle Plugin 8.10.1, compile SDK 36, target SDK 35, min SDK 26. Media3 is pinned to 1.11.1. GLES 3.0 is required.

```sh
bash .github/scripts/bc1-media-fixtures.sh
cd BC-1
gradle -Pbc1SideBySide testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Fixture generation requires ffmpeg. Device checks run through `.github/scripts/bc1-device-checks.sh`. It retains screenshots and the acceptance export before test-app cleanup. Test sources are not included in the installable APK. CI APKs use ephemeral CI debug signing; the delivered preview APK uses the retained private v0.3 preview signing key.

References: [Media3 releases](https://developer.android.com/jetpack/androidx/releases/media3), [Compositions](https://developer.android.com/media/media3/transformer/composition), and the pinned Media3 1.11.1 source jars from Google Maven.
